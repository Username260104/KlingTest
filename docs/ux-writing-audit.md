# Entresol UX Writing / Voice & Tone Audit

## 1. 감사 범위

- 홈 랜딩의 히어로, 신뢰 정보, 사용 유형, 문의 준비, 공급 절차, 최종 CTA
- 헤더와 푸터의 버튼·링크·정책 문구
- 문의 화면의 제목, 안내, 필드명, placeholder, select option, 동의문
- 로딩, 검증 오류, 입력 확인, 프로토타입 상태 문구
- 페이지 제목, 메타 설명, Open Graph·X 문구, 접근성 라벨

## 2. 기존 언어의 인상

기존 카피는 신중하지만 사업 안내문이나 내부 요구사항서에 가까웠다. `기업`, `공급`, `문의`, `예상`, `확인`, `필요`, `안내`가 여러 구역에서 반복됐고, 각 섹션이 다른 질문에 답하기보다 거의 같은 내용을 재진술했다.

핵심 문제는 다음과 같다.

- `확인해 안내합니다`가 반복돼 소극적이고 기계적인 인상을 주었다.
- 사용 유형 카드가 모두 `상황입니다`로 끝나 고객이 얻는 가치보다 분류 기준을 설명했다.
- `편하게 남겨주세요`처럼 의미가 분명하지 않은 친절함과 반복되는 공적 표현이 한 페이지 안에 섞여 있었다.
- 글로벌 CTA, 카드 CTA, 폼 제출 CTA가 서로 다른 규칙을 사용했다.
- 실제로는 전송하지 않는 폼의 버튼이 `문의하기`로 표시돼 동작과 문구가 일치하지 않았다.
- 기본 브랜드는 `Entresol`, 공급 주체는 `HRC ENT`로 표시되지만 두 명칭의 관계는 최종 확정 정보가 아니므로 임의 해석을 추가하지 않았다.

## 3. Verbal Identity

### 믿을 만한 실무 담당자

Entresol의 목소리는 **‘Kling 크레딧을 처음 구매하는 고객에게 필요한 내용을 쉽게 설명하는 경험 있는 실무 담당자’**다.

1. **쉽게 말한다** — `도입 규모`, `공급 체계` 같은 추상 명사보다 `얼마나 만들지`, `언제 필요한지`처럼 일상적인 말을 쓴다.
2. **고객에게 바로 말한다** — 고객을 3인칭으로 분류하지 않고 `알려주세요`, `함께 계산합니다`처럼 대화한다.
3. **필요한 말만 한다** — 섹션마다 같은 메시지를 반복하지 않고, 그 위치에서 고객이 알아야 할 내용만 말한다.
4. **과장하지 않는다** — 가격 우위·독점·속도를 임의로 약속하지 않는다.

## 4. Voice & Tone 운영 원칙

| 상황 | 톤 | 문장 규칙 |
|---|---|---|
| 서비스·신뢰 정보 | 단정하고 정확함 | `-합니다`, `-입니다` 중심의 능동형 |
| 사용 유형·절차 | 실무적이고 상담적임 | 기준과 결과를 한 문장으로 연결 |
| 폼 안내 | 직접적이고 예의 바름 | `-해 주세요` 사용, 과도한 존칭 금지 |
| 검증 오류 | 책임을 묻지 않고 해결을 제시 | `항목 + 필요 행동` 구조 |
| 로딩·상태 | 짧고 사실적임 | 현재 상태만 안내 |
| 프로토타입·정책 | 오해가 없도록 명시적임 | 전송·저장 여부와 추후 조치를 분리 |

### 문장과 존댓말

- 기본 종결은 `-합니다` 체로 통일한다.
- 사용자의 행동을 요청할 때만 `-해 주세요`를 사용한다.
- 레이블과 카드 제목은 명사형으로 쓴다.
- 한 문장은 원칙적으로 두 절을 넘지 않는다.
- `담당자 성함`처럼 과도한 존칭은 `담당자명`으로 간결하게 쓴다.

### CTA 체계

- 전역 주 CTA: `공급가 문의하기`
- 사용 유형 CTA: `[유형명] 문의하기`
- 프로토타입 폼 버튼: `입력 내용 확인하기`
- 상태 후 복귀 CTA: `입력 내용 수정하기`

CTA는 목적어와 행동을 바로 이해할 수 있게 쓴다. 실제 전송이 없는 동작을 `문의 보내기`로 표시하지 않는다.

### 핵심 용어

- 우선: `사용량`, `구매 일정`, `필요한 크레딧`, `공급가`, `미정`
- 제한: `상황입니다`, `확인해 안내합니다`, `공식 공급 체계`, `도입 단계`, `사용 규모`, `편하게`
- 금지: `국내 최초`, `독점`, 확인되지 않은 할인율·최저가·공급 속도
- 조건부 표현은 사이트 전체에서 각 1회만 사용한다. `Kling 국내 공식 총판`은 히어로에, `Kling 본사 직접 계약`은 공식 공급 구역에 배치한다.

## 5. 적용 결과

- 히어로는 서비스 범위와 공급 제안을 말하고, 사용 유형·준비 정보·절차는 각각 다른 의사결정을 돕도록 역할을 분리했다.
- 구역별 영문 eyebrow는 짧은 기능명으로 통일했다.
- 전역 CTA와 맥락형 CTA를 구분하고, 폼 버튼은 실제 동작에 맞춰 교정했다.
- 필수 필드의 브라우저 검증 문구를 서비스 톤으로 통일했다.
- 프로토타입 안내는 `전송하지 않음`과 `저장하지 않음`을 항상 직접 밝히도록 정리했다.
- 메타 설명과 소셜 공유 문구도 실제 고객이 쓰는 `구매`, `수량`, `일정` 중심으로 바꾸었다.

## 6. 추후 확정이 필요한 항목

- `Entresol`과 `HRC ENT`의 대외 표기 관계
- `Kling 국내 공식 총판`, `Kling 본사 직접 계약` 문구의 대외 공개 승인
- 정식 문의 기능 적용 전 개인정보 수집·이용 동의문과 처리방침
