## 1. 프로젝트 목표와 범위

### 1.1 목표

광고대행사와 영상제작사가 해외 사업자와 직접 계약하지 않고도 국내 사업자를 통해 Kling과 Seedance를 검토·도입할 수 있다는 점을 설명하고, 방문자를 다음 두 전환으로 연결한다.

1. 도입 상담 신청
2. 기업 견적 요청

사이트가 전달해야 할 핵심 가치는 다음과 같다.

> 해외 계약과 결제의 번거로움 없이, 국내 기업과 계약하고 Kling과 Seedance를 업무에 도입할 수 있도록 계약·결제·공급·기술지원을 통합 제공합니다.

단, 국내 계약, 원화 결제, 세금계산서, 기술지원, 모델 공급과 관련된 표현은 실제 제공 가능한 범위가 확인된 항목만 노출한다.

### 1.2 1차 포함 범위

- 단일 반응형 랜딩페이지
- Kling·Seedance 모델 및 활용 분야 소개
- 국내 계약·결제·지원 구조 설명
- 계약·가격 방식과 도입 절차 안내
- 회사 및 파트너 관계 정보
- 상담·견적 통합 문의 폼
- 개인정보처리방침
- 서비스 이용안내
- 기본 SEO, 전환 분석, 스팸 방지, 오류 모니터링

### 1.3 1차 제외 범위

- 온라인 직접 결제
- 회원가입과 로그인
- 고객 대시보드
- API 키 자동 발급
- 실시간 사용량 조회
- 자동 크레딧 충전
- 자동 견적 계산
- 고객용 기술 문서 포털

제외 기능은 실제 문의량, 계약 전환율, 고객 요구가 확인된 뒤 별도 단계로 검토한다.

## 3. 사이트 메뉴와 정보구조

### 3.1 데스크톱 상단 메뉴

헤더는 스크롤 시 상단에 고정하고 메뉴를 6개로 제한한다.

| 메뉴 | 앵커 | 포함 내용 |
|---|---|---|
| 서비스 | `#service` | 공급 서비스 개요와 통합 지원 구조 |
| 지원 모델 | `#models` | Kling·Seedance 비교와 공급 가능 범위 |
| 도입 혜택 | `#benefits` | 국내 계약, 원화 결제, 세금계산서, 한국어 지원 등 |
| 활용 분야 | `#use-cases` | 광고, 제품 영상, 숏폼, 프리비주얼, 대량 제작, 서비스 개발 |
| 계약·도입 | `#plans` | 계약 방식, 가격 원칙, 도입 절차 |
| 회사·파트너 | `#company` | 회사 정보, 계약 관계, 공급 및 지원 범위 |

헤더 우측에는 기본 CTA인 `기업 견적 요청` 버튼을 배치한다. `FAQ`와 법적 문서는 푸터에서 접근할 수 있게 해 상단 메뉴를 간결하게 유지한다.

### 3.2 URL 구조

| URL | 우선순위 | 목적 |
|---|---:|---|
| `/` | P0 | 전체 랜딩페이지와 문의 폼 |
| `/privacy` | P0 | 개인정보처리방침 |

1차 문의 완료는 별도 페이지 이동보다 폼 내부의 성공 상태로 처리한다. 법적 문서는 모달이 아니라 독립 URL로 제공해 공유, 인쇄, 접근이 가능하게 한다.

### 3.4 이용 절차 표시 내용

`#plans` 안의 도입 절차는 다음 순서로 고정하고, 각 단계에 고객이 준비할 정보와 공급사가 제공할 결과를 짧게 표시한다.

1. 상담 또는 견적 요청
2. 사용 목적과 예상 사용량 확인
3. 적합 모델과 계약 방식 제안
4. 계약 체결과 원화 결제
5. API 사용권 또는 크레딧 제공
6. 연동 지원과 운영 기술지원

계약 체결 전 상담은 최종 공급 조건의 확정이나 계약 성립이 아니라는 점을 가격·계약 안내에 함께 표시한다.

### 4.1 히어로 권장 구조

- 보조 문구: `광고대행사·영상제작사를 위한 AI 영상 생성 모델 공급`

위 문구도 실제 계약·공급 가능 상태가 확인된 뒤 사용한다. 계약 전 공개가 필요하다면 `도입 사전 상담`, `공급 준비 중` 등 사실에 맞는 중립 문구로 별도 승인받는다.

모델 비교는 우열 순위가 아니라 고객의 선택 기준을 제공해야 한다.

- 입력 방식: 텍스트·이미지 등 실제 지원 범위
- 주요 강점
- 적합한 제작 유형
- 제공 가능한 해상도·길이·기능 `[확정 필요]`
- API 제공 범위와 제한 `[확정 필요]`
- 과금 또는 크레딧 산정 기준 `[확정 필요]`
- 지원 가능한 연동 범위 `[확정 필요]`

모델 사양은 변경 가능성이 있으므로 콘텐츠에 최종 검토일과 담당자를 기록한다. 근거가 없는 `최고`, `가장 빠른`, `독점` 등의 표현은 사용하지 않는다.

### 4.3 파트너 관계 표현 원칙

| 상태 | 공개 원칙 |
|---|---|
| 계약 전 | 공급 또는 공식 지위를 확정적으로 표현하지 않는다. 로고와 공식 파트너 배지를 사용하지 않는다. |
| 계약 협의 중 | 협의 사실의 공개가 허용된 경우에만 승인된 문구를 사용한다. |
| 계약 체결 후 | 계약서상 정확한 지위, 지역, 기간, 모델, API, 재공급 범위만 표현한다. |
| 브랜드 사용 승인 후 | 별도 브랜드 가이드에 맞춰 로고, 제품 화면, 생성 결과물을 사용한다. |

`공식 총판`, `독점 파트너`, `공식 리셀러`, `본사 인증 공급사`는 계약서와 브랜드 사용 승인으로 근거가 확인되기 전에는 금지 문구로 관리한다.

### 4.4 가격·계약 표시 원칙

초기에는 변동 가능한 숫자 단가표보다 네 가지 계약 구조와 견적 기준을 공개한다.

| 계약 구조 | 화면 표시 예시 | 확인할 조건 |
|---|---|---|
| 테스트·PoC | 테스트 사용량은 별도 문의 | 테스트 제공 가능 여부와 한도 |
| 프로젝트 크레딧 | 프로젝트 단위 맞춤 견적 | 모델, 생성 옵션, 예상 건수, 사용 기간 |
| 월 사용량 계약 | 사용량 구간별 할인 | 최소 사용량, 초과 정산, 계약 기간 |
| 대량 사용 계약 | 기업별 별도 협의 | 대량 할인, 기술지원, 정산 조건 |

견적 산정 기준, 부가세 포함 여부, 견적 유효기간, 공급사 단가 또는 환율 변동 시 처리 원칙은 실제 정책을 확정한 뒤 서비스 이용안내와 함께 표기한다.

## 5. CTA와 문의 폼 설계

### 5.1 CTA 연결 규칙

상담 폼과 견적 폼을 중복 제작하지 않고 하나의 통합 폼을 사용한다. CTA에 따라 폼의 선택값만 미리 설정한다.

> 원 기획의 `상담 신청 폼`과 `견적 요청 폼`을 화면·API 수준에서는 하나로 통합하는 변경 제안이다. `[변경 승인 필요]` 두 CTA는 유지하며 `문의 유형`을 접수 원장, 담당자 알림, CRM까지 구분해 저장한다.

| CTA 위치 | 버튼명 | 폼에 미리 설정할 값 |
|---|---|---|
| 히어로 | 도입 상담 신청 | 문의 유형=`도입 상담` |
| 히어로·헤더·하단 | 기업 견적 요청 | 문의 유형=`견적 요청` |
| Kling 모델 카드 | Kling 도입 문의 | 희망 모델=`Kling` |
| Seedance 모델 카드 | Seedance 도입 문의 | 희망 모델=`Seedance` |
| 계약 방식 카드 | 맞춤 견적 받기 | 선택한 계약 방식 |

CTA 클릭 시 `#inquiry`로 이동하고 미리 설정한 값을 사용자에게 보여준다. 공유와 새로고침 후에도 선택을 유지해야 하면 `/?intent=quote&model=kling#inquiry`처럼 비개인 식별값만 쿼리에 기록한다. 개인정보와 자유 입력값은 URL에 넣지 않는다.

### 5.2 폼 단계

모바일 입력 부담을 줄이기 위해 시각적으로 두 단계로 구성하되, 이전 입력값은 유지한다.

#### 1단계: 기본 정보

| 항목 | 필수 여부 | 규칙 |
|---|---:|---|
| 문의 유형 | 필수 | 도입 상담 / 견적 요청 |
| 회사명 | 필수 | 2~100자 |
| 담당자명 | 필수 | 2~50자 |
| 이메일 | 조건부 필수 | 이메일 또는 연락처 중 하나는 필수 |
| 연락처 | 조건부 필수 | 이메일 또는 연락처 중 하나는 필수 |
| 희망 모델 | 필수 | Kling / Seedance / 모두 / 미정 |

#### 2단계: 도입 정보

| 항목 | 필수 여부 | 권장 입력 방식 |
|---|---:|---|
| 사용 목적 | 필수 | 활용 분야 복수 선택 + 기타 |
| 예상 월 생성 규모 | 필수 | 테스트·PoC / 100건 미만 / 100~499건 / 500~1,999건 / 2,000건 이상 / 미정 |
| 평균 영상 조건 | 선택 | 평균 길이, 목표 해상도, 주요 모델 옵션; 모르면 `상담 필요` |
| 문의 내용 | 필수 | 자유 입력, 최대 2,000자 |
| 예상 월 예산 | 선택 | 금액 구간 선택 |
| 희망 계약 방식 | 선택 | 크레딧 / 원화 충전 / 월 사용량 / 맞춤 계약 / 미정 |
| API 연동 필요 | 선택 | 필요 / 불필요 / 상담 필요 |
| 기술지원 필요 | 선택 | 필요 / 불필요 / 상담 필요 |
| 도입 희망 시기 | 선택 | 즉시 / 1개월 이내 / 1~3개월 / 3개월 이후 / 미정 |
| 업종·회사 규모·홈페이지·주요 사업 분야 | 선택 | 추가 정보 영역에 배치 |
| 부서·직급 | 선택 | 추가 정보 영역에 배치 |
| 사업자등록번호 | 선택 또는 계약 단계 수집 | 초기 문의에서 꼭 필요하지 않으면 제외 |
| 개인정보 수집·이용 동의 | 필수 | 전문 보기와 정책 버전 기록 |

생성 건수 구간은 초기 규모를 파악하기 위한 값이다. 최종 크레딧과 견적은 평균 길이, 해상도, 모델 옵션을 함께 확인해 산정하며, 고객이 이를 모를 때는 상담 과정에서 보완한다.

1차 MVP에서는 문의 대응에 필요하지 않은 마케팅 수신 동의를 받지 않는다. 추후 뉴스레터나 프로모션 발송이 실제 범위에 포함될 때 목적, 채널, 보유기간, 철회 방법을 정한 뒤 별도 선택 동의로 추가한다.

### 5.3 제출 처리 흐름

```text
사용자 입력
→ 브라우저 기본 검증
→ 서버 동일 규칙 재검증
→ 중복·스팸 확인
→ 문의 원장 또는 CRM에 영속 저장
→ 접수 식별번호 생성
→ 담당자 알림
→ 사용자에게 접수 완료와 후속 절차 안내
```

이메일 알림만 발송하고 문의 원장을 남기지 않는 방식은 사용하지 않는다. 알림 장애가 발생해도 접수 데이터가 보존되어야 한다.

### 5.4 상태와 예외 처리

- 제출 중: 버튼 비활성화와 진행 상태 표시
- 검증 오류: 해당 입력과 오류 메시지를 연결하고 첫 오류로 포커스 이동
- 네트워크 오류: 입력값을 유지한 채 재시도 제공
- 중복 클릭: 동일 문의가 여러 번 생성되지 않도록 요청 키 적용
- 제출 성공: 접수 완료, 접수 식별번호, 예상 연락 방식과 `[회신 목표시간 확정 필요]` 표시
- 알림 실패: 문의는 저장하고 운영자에게 별도 장애 알림

## 6. 모바일·반응형·접근성 원칙

- 모바일 헤더에는 로고, 메뉴 버튼, 핵심 CTA 하나만 노출한다.
- 모바일 메뉴를 열면 6개 앵커와 견적 CTA를 표시하고, 항목 선택 후 메뉴를 닫는다.
- 모바일 메뉴가 닫히면 포커스를 메뉴 버튼으로 돌려보내고 배경 콘텐츠 포커스를 적절히 제한한다.
- 화면 하단에는 `상담 신청`과 `견적 요청` 2분할 고정 바를 배치한다.
- 하단 고정 바는 기기 safe area를 반영하고, 키보드가 열리거나 `#inquiry`가 화면에 들어오면 숨겨 입력 영역을 가리지 않는다.
- 모델 비교는 작은 화면에서 가로 스크롤 표 대신 동일 기준의 세로 카드로 전환한다.
- 도입 절차는 모바일에서 세로 타임라인으로 표시한다.
- FAQ는 키보드로 조작 가능한 아코디언으로 구현한다.
- 앵커 이동 시 고정 헤더 높이만큼 여백을 둔다.
- 버튼과 입력 요소의 터치 영역은 최소 44px을 목표로 한다.
- 제목 구조, 입력 레이블, 오류 연결, 대체텍스트, 명확한 포커스 표시를 제공한다.
- 색상만으로 상태를 구분하지 않고 충분한 명도 대비를 확보한다.
- `prefers-reduced-motion`에서 자동 재생과 큰 모션을 줄인다.
- 접근성 목표는 WCAG 2.2 AA 수준으로 설정한다.

### 8.2 문의 데이터 최소 구조

- 접수 ID와 접수 시각
- 문의 유형
- 회사명과 담당자명
- 이메일·연락처 중 제공된 값
- 희망 모델, 사용 목적, 예상 사용량
- 선택 도입 정보와 문의 내용
- 개인정보 동의 버전과 동의 시각
- 사전에 정의한 캠페인 ID, 정규화한 유입 출처, 최초 CTA 등 최소 전환 정보
- 영업 처리 상태와 담당자

수신한 UTM 쿼리와 referrer URL 원문은 저장하지 않는다. 자사가 발급한 캠페인 ID만 허용 목록으로 매핑하고, referrer는 쿼리와 경로를 제거한 출처 도메인 수준으로 정규화한다. 개인정보를 URL, 분석 이벤트, 일반 오류 로그에 포함하지 않는다. IP와 사용자 환경 정보는 보안상 필요한 최소 범위와 기간만 처리하도록 별도 검토한다.

## 9. 비기능 요구사항

### 9.1 성능

### 9.2 보안과 개인정보

- HTTPS 강제와 기본 보안 헤더 적용
- 서버 입력 검증, 길이 제한, 출력 이스케이프 적용

- 개인정보 관련 문구와 처리방침은 국내 법률 전문가 또는 개인정보 책임자가 최종 검토

## 10. 분석 이벤트와 KPI

1차 권장안은 비필수 쿠키를 쓰지 않는 최소 분석이다. 선택한 도구가 비필수 쿠키나 제3자 추적을 사용한다면 유효한 선택 동의 전에는 해당 도구를 로드하지 않고, 동의 배너·설정 변경·철회 흐름을 P0 범위에 추가한다. 최종 방식은 개인정보 책임자의 검토를 거친다.

### 10.1 이벤트 맵

| 이벤트 | 발생 시점 | 포함 가능 정보 |
|---|---|---|
| `cta_click` | 주요 CTA 클릭 | 위치, CTA 유형, 미리 선택한 모델·계약 방식 |
| `form_start` | 첫 입력 또는 다음 단계 진입 | 문의 유형, 유입 위치 |
| `form_step_complete` | 기본 정보 단계 완료 | 단계 번호만 기록 |
| `form_validation_error` | 제출 또는 단계 이동 실패 | 필드 이름과 오류 유형, 입력값 제외 |
| `form_submit_success` | 서버 저장 성공 | 접수 ID를 분석 도구에 보내지 않고 성공 여부만 기록 |
| `form_submit_failure` | 서버 처리 실패 | 오류 코드, 개인정보 제외 |
| `contact_link_click` | 전화·이메일 링크 클릭 | 링크 유형과 위치 |

회사명, 담당자명, 이메일, 연락처, 문의 내용은 분석 이벤트로 전송하지 않는다.

### 10.2 운영 KPI

- CTA 클릭률
- 문의 폼 시작률
- 폼 제출 완료율
- 유효 문의율
- 상담 후 견적 전환율
- 견적 후 계약 전환율
- 최초 응답시간
- 모델별 관심도와 예상 사용량 분포
- 스팸 문의 비율

초기 4주 데이터를 기준선으로 삼고, 방문 수가 충분하지 않을 때는 작은 수치 차이로 성급하게 UI를 변경하지 않는다.

## 13. QA 핵심 시나리오

1. 히어로의 각 CTA가 정확한 문의 유형을 선택한다.
2. 모델 카드 CTA가 해당 모델을 선택하고 폼으로 이동한다.
3. 이메일만, 연락처만, 둘 다 입력한 경우의 조건부 검증이 각각 정상 동작한다.
4. 개인정보 필수 동의 없이 제출할 수 없고, MVP에서는 별도 마케팅 수신 동의를 수집하지 않는다.
5. 중복 클릭과 새로고침으로 문의가 중복 저장되지 않는다.
6. 알림 서비스 장애 시 문의 원장에는 데이터가 남고 운영자에게 장애가 표시된다.
7. 분석 도구, URL, 오류 로그에 개인정보가 나타나지 않는다.
8. 키보드와 화면낭독기 흐름으로 메뉴·FAQ·폼을 사용할 수 있다.
9. 영상과 이미지 로딩 실패 시에도 핵심 메시지와 CTA가 보인다.
10. 스테이징은 검색되지 않고 운영 사이트만 검색 가능하다.
11. 개인정보처리방침의 수집 항목·보유기간이 실제 폼·저장소와 일치한다.
12. 파트너 지위, 모델 사양, 가격, 지원 범위가 승인표와 일치한다.
13. 비필수 추적을 쓰는 경우 동의 전에는 차단되고, 거부·철회 후에도 다시 로드되지 않는다.

## 14. 출시 차단 조건

다음 중 하나라도 해결되지 않으면 운영 공개를 보류한다.

- 공식 파트너·총판 표현에 계약상 근거가 없음
- 모델명, 로고, 생성 결과물 사용 권한이 확인되지 않음
- 사이트 문구와 실제 공급 API·가격·지원 범위가 다름
- 회사명, 사업자, 계약·결제 주체를 공개할 수 없음
- 개인정보의 저장 위치, 보유기간, 접근·삭제 절차가 정해지지 않음
- 문의를 영속 저장하지 않고 이메일 발송에만 의존함
- 운영 담당자와 회신 기준이 지정되지 않음
- 테스트 문의가 저장 또는 담당자 전달 과정에서 유실됨
- 개인정보가 분석 도구, URL, 공개 로그에 포함됨
- 분석 도구의 쿠키·제3자 전송 여부와 동의 전략이 확정되지 않음
- 개인정보처리방침과 필수 동의 문구가 승인되지 않음

| 대형 영상으로 성능 저하 | 이탈과 SEO 저하 | 정적 히어로 우선, 포스터·압축·지연 로딩 |
| 문의 후 대응 지연 | 계약 전환과 신뢰 저하 | 담당자·백업 담당자·회신 목표시간 지정 |

## 17. 즉시 확정해야 할 입력값

개발 착수 전 아래 항목부터 한 장의 의사결정표로 확정한다.

1. 공개할 회사명, 대표자, 사업자등록번호, 주소, 연락처, 이메일
2. 계약과 세금계산서 발행 주체
3. Kling·Seedance와의 현재 계약 상태와 공개 가능한 정확한 명칭
4. 모델명·로고·생성 결과물의 사용 가능 범위
5. 실제 공급 가능한 모델, API, 크레딧, 지역 범위
6. 국내 계약·원화 결제·세금계산서 제공 가능 시점
7. 가격 산정 원칙, 최소 사용량, 견적 유효기간
8. 기술지원 채널, 시간, 범위, 회신 목표시간
9. 문의 접수 원장으로 사용할 CRM 또는 데이터베이스
10. 담당자 알림 채널과 주·백업 수신자
11. 개인정보 보유기간과 삭제 책임자
12. 운영 도메인, 호스팅, 분석 도구와 쿠키·추적 동의 방식
13. 사이트 공개 목표일과 최종 승인자
14. 상담·견적 CTA를 하나의 통합 폼으로 처리하는 변경안 승인

이 14개 항목이 확정되면 와이어프레임, 최종 카피, 기술 설계를 병렬로 시작할 수 있다.
