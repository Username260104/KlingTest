# 빠른 프론트엔드 프로토타입 범위

기존의 [상세 구현 계획](./사이트-구현-계획.md)은 외주 제작과 후속 운영 추적용으로 그대로 보존한다. 이번 작업은 사업 방향을 빠르게 눈으로 확인하기 위한 프론트엔드 프로토타입만 다룬다.

현재 화면 스타일은 Kling Creative Studio에서 확인한 다크 테마 토큰을 기준으로 구성한다. 페이지 구조와 내용 검토가 목적이며, Kling 로고·심볼·제품 화면은 직접 복제하지 않는다.

## 이번에 보는 것

- 페이지별 이동 흐름
- 사이트의 전체적인 색감과 B2B 분위기
- 메뉴와 CTA 배치
- Kling·Seedance 비교 화면
- 계약 방식과 도입 절차 화면
- 회사·파트너 정보가 들어갈 위치
- 상담·견적 폼과 완료 화면의 느낌
- 페이지별로 추가 준비해야 할 콘텐츠

## 페이지 구조

| 페이지 | URL | 확인할 내용 |
|---|---|---|
| 홈 | `/` | 전체 메시지, 서비스 개요, 모델·활용·절차 요약 |
| 지원 모델 | `/models` | Kling·Seedance 비교 방식과 필요한 사양 정보 |
| 계약·도입 | `/plans` | 네 가지 계약 구조와 여섯 단계 도입 흐름 |
| 회사·파트너 | `/company` | 회사 정보, 계약 관계, 공급·지원 범위 위치 |
| 상담·견적 | `/contact` | 입력 항목, CTA별 사전 선택, 완료 화면 |

## 화면 원칙

- 서비스명은 `Entresol`을 사용한다.
- 모델이나 파트너 관련 확정되지 않은 정보는 대괄호 자리표시자로 보여준다.
- 가격은 숫자를 넣지 않고 `별도 문의`, `맞춤 견적`, `사용량별 할인`로 표시한다.
- 상담과 견적은 하나의 폼에서 문의 유형만 구분한다.
- 실제 데이터는 전송하지 않으며 제출 시 프론트엔드 완료 화면만 보여준다.
- 데스크톱과 모바일에서 모두 페이지 이동과 입력 화면을 확인할 수 있게 한다.

## 이번에 하지 않는 것

- 문의 데이터 저장과 이메일 전송
- CRM·분석 도구 연동
- 개인정보처리방침·이용약관 작성
- 온라인 결제, 회원가입, API 키 발급
- 실제 가격·계약·파트너 문구 확정
- 고객 대시보드와 사용량 조회

## 보고 난 뒤 결정할 것

1. 사이트 분위기와 임시 브랜드 방향이 적절한지
2. 단일 랜딩페이지가 나은지 현재의 다섯 페이지 구성이 나은지
3. 홈에서 강조할 핵심 문구
4. 실제 회사명과 회사 정보
5. 모델별로 공개 가능한 사양과 사례
6. 상담 폼에서 빼거나 추가할 항목

이 여섯 가지가 정해지면 외주 업체에 기존 상세 계획서와 이 프로토타입을 함께 전달하면 된다.
